# 知识页面规范

`wiki/` 按知识对象和问题组织解释。定位、范围与当前画像见 [SELF](SELF.md)，阅读入口见 [INDEX](INDEX.md)。

## 先确定边界与组织方式

初始化时，AI 先与用户讨论用途、服务对象、收录与不收录的内容，以及需要解释到什么程度。在此基础上检索相关材料，推荐目录和候选页面，说明各目录放什么、各页面解决什么问题，以及页面之间的关系。用户调整并确认后，再将约定写入本文件，将定位和当前计划写入 SELF。

推荐方案应具体到可讨论的目录与页面，不能只让用户自行提供目录。已有内容优先复用；尚无正文的候选页面保留在计划中，有实际内容时再创建并加入 INDEX。以后需要实质调整边界或目录设计时，先说明理由与影响，再与用户确定。

## 页面组织

- 根据用户需求和实际内容确定分类，不为分类完整而建立空目录。
- 每页围绕一个清楚的对象或问题展开，优先补充已有页面；新页面应有独立的解释作用。
- 页面能够独立阅读，包含理解主题所需的解释、条件和来源。已有内容可通过链接复用。
- 文件名保持清楚、稳定；页面标题准确表达内容。README、SELF 和 INDEX 承担管理职责，不作为知识页面计算。

## 表达与来源

开头建立对对象的整体认识：它是什么，在什么场景下起什么作用，总体怎样工作，有哪些关键限制。正文沿这条主线展开，说明各部分为何存在、如何配合，再进入局部机制与证据。解释范围由页面职责决定，局部主题说明它与相关方法或系统的关系即可，不必重讲整个领域。

- 用具体对象和动作表达关系，术语与符号在读者首次需要时解释；公式说明对象、符号、假设和必要推理，步骤说明作用与衔接。
- 前置知识已有充分解释时，说明与当前问题的关系并链接；读取目标确认它提供所需解释。核心解释不能只用链接代替，尚缺的必要知识在本页或适当页面补足。
- 每段提供必要的新信息，删除重复结论、空泛评价和无用的过程说明。写完逐段检查：删掉后不影响理解、判断或使用的内容就删；对象、动作或指代需要猜的句子改清楚。
- 按实际需要保留推理、例子、反例和限制，不为简短删去关键信息，也不机械填充统一标题。说不清的关系先查明，不能靠换词掩盖。
- 在具体陈述附近注明依据，使读者能够辨识来源及所用版本，并回到相关位置核对。
- 区分来源陈述、整理者的理解或推导、实际验证和仍待核实的判断。来源中的条件随结论保留。
- 原始资料的保存与版本规则见 [raw 说明](../raw/README.md)。

初始化时按实际用途和读者基础，选取适用的解释要求。以下是帮助判断内容的参考，不要求统一页面分类、标题或字段；一页可以承担多种作用，具体要求由该 Wiki 的约定确定。

复核时先只依靠正文与必要链接，检查读者能否说清对象的作用、整体思路和关键关系，再回查来源验证事实与条件。细节准确、引用充分不代替整体解释；审核者自己知道的内容也不算页面已经说明。

| 页面主要用途 | 重点解释什么 |
| --- | --- |
| 理解概念 | 含义、必要边界、与相关概念的区别，以及帮助理解的例子。 |
| 理解方法 | 要解决的问题、整体思路、各步骤的作用与衔接、关键机制、前提和限制。 |
| 比较分析 | 比较维度、可比条件、差异及各自的依据。 |
| 执行操作 | 前置条件、步骤、结果如何检查，以及来源支持的失败处置。 |

## 链接与导航

- 使用标准 Markdown 相对链接，文件链接包含扩展名，路径相对于当前页面。
- 在论述中说明相关页面的作用，例如前置知识、方法联系或实现细节。
- INDEX 组织实际存在的知识页面及阅读路径；目标、范围、覆盖情况和下一步由 SELF 说明。
- 图像和附件有实际需要时放在 `assets/` 中，正文使用相对路径并保留必要的来源说明。

## 维护

- 新增、移动、合并或删除页面后，同步相关链接、导航和附件。
- 知识覆盖或建设方向发生实质变化时，更新 SELF；已解决的问题不继续作为当前缺口。
- 检查结果说明实际核对的范围。链接和格式正确不等于事实、解释或推导已经核验。

## 检查约定

AI 根据已确认的 raw、Wiki 约定推荐具体检查项，与用户确定后保存。raw 只做[来源资料规则](../raw/README.md)中的基础检查，Wiki 检查覆盖以下六类：

| 检查项 | 检查内容 |
| --- | --- |
| 内容质量 | 标题与正文一致，页面解决明确的问题；对象的作用、整体思路和关键关系清楚，必要的概念、前提、机制、例子和限制有解释。句子对象与指代明确，无重复空话、空页、占位内容或原文堆砌；精简未丢失必要推理与证据。 |
| 依据与引用 | 重要结论、数字、公式和比较有可回查的依据；引用支持对应陈述，适用条件及来源观点、整理者解释和实际验证得到区分。 |
| 链接与导航 | 文件、图片、附件和锚点有效，知识页面能从 INDEX 到达，链接描述与目标内容相符，能够承接所需解释。 |
| 目录与页面组织 | 符合已确认的范围和目录设计，页面职责清楚；检查重复内容、放错位置、主题混杂和缺少的必要关联。 |
| 一致性与更新 | 概念、定义、符号和跨页结论一致；先对齐对象、版本和条件，再判断冲突或新材料是否需要更新旧结论。 |
| 当前状态与知识缺口 | SELF、INDEX 与实际内容一致，计划和已完成内容分明；按用途检查重要解释、证据和待整理资料中的知识缺口。 |

完整检查覆盖上述范围；日常修改检查受影响的条目、页面和相关链接。使用 [wiki-lint](../.agents/skills/wiki-lint/SKILL.md) 组织检查：工具核对结构，AI 做 raw 基础查看，并复用 [wiki-review](../.agents/skills/wiki-review/SKILL.md) 核对知识内容。发现疑似过时内容或重要缺口时，按用户约定定向检索并读取相关材料。

结果给出位置、问题、依据和建议，区分已确认问题、待核实疑点与改进建议，说明未覆盖部分。文章较旧、资料尚未写入 Wiki 或概念没有独立页面，本身不算错误；检查通过不表示未核验内容也正确。
