# Wiki Init

## 任务

基于通用模板完成用户自己的 Wiki 初始化。交付后，用户和新进入的 Agent 能从文件中理解 Wiki 的目的、内容边界、知识质量要求、实际已有内容、工作方式和下一步。依据七项通用指标验收，交付可定位的依据。

本 Skill 的当前设计见 [README](README.md)。执行所需的动作与判断写在本文件中；初始化使用同一项目中的模板管理文件。

## 输入

结合对话和目标目录取得：目标位置、用途与主题、内容范围、希望怎样使用知识，以及已有资料与文件。结合读者基础、代表性问题及预期结果判断解释深度；按需要补充资料类型和维护偏好。

用户在模板副本中要求初始化当前 Wiki 时，以该副本为目标；要求创建到其他位置时，明确目标目录。能从已有内容判断的信息先读取，不重复询问。没有初始资料时仍可完成结构与约定的初始化。

## 原则

1. **主动多轮澄清需求。** 用户可以从不完整、笼统的想法开始。主动发现缺口，优先用选择题，先给例子与建议帮助表达，再追问、核对并修正理解；每轮聚焦一小组关键问题。需求足以支撑具体方案时再进入下一阶段，不按提问轮数判断完成。
2. **按顺序主动推荐。** 先讨论用途与边界，再依次确定 raw 来源与保存形式、整体文件夹、Wiki 页面、检查与工作约定。主动检索材料并提出具体设计，说明推荐理由和重要取舍，让用户选择、修改或补充；普通实现细节自主决定。
3. **复用已明确的信息与授权。** 方案已经明确时继续范围内的定制与核对，不重走已完成的讨论。用户仅要求讨论时交付分析与方案。
4. **展示有依据的百分比进度。** 从首轮起，每轮澄清与方案讨论都显示百分比和当前环节；实施时在关键进展处更新。依据已明确事项和实际产物估算，达到阶段完成条件后才能进入下一区间，验收交付完成才显示 100%。
5. **保护与复用已有内容。** 修改前读取目标文件，只调整方案影响的内容，保留有效约定、资料、知识和 Git 配置。复制模板管理文件时不复制 `.git/`，不改写原始证据。
6. **范围与内容如实记录。** 计划、已保存资料、已形成知识和实际核验分别说明；导航指向实际文件，知识分类按需要和内容建立。结构初始化、知识质量和实际运行结果分别评估。

## 工作步骤

按以下顺序推进：**用途与边界 → raw 来源与保存形式 → 整体文件夹设计 → Wiki 页面内容与关系 → 检查与工作约定 → 定制文件 → 核对与交付**。每个环节先给推荐方案，再听取用户选择与建议；重要问题明确后进入下一环节。复用已有结论，新回答影响先前决定时返回相应环节修正。

从首轮起，在每轮澄清、方案讨论的回复开头显示简短百分比进度；实施时在关键进展处更新。按下表判断阶段：

| 阶段 | 进度区间 | 进入下一区间的条件 |
| --- | --- | --- |
| 明确用途与边界 | 0–25% | 用途、读者基础、初步边界、来源现状和目标位置已清楚。 |
| 确定组织与工作方案 | 25–50% | raw 来源与保存形式、整体文件夹、页面设计、检查与工作约定已确定。 |
| 定制文件 | 50–75% | 已确认方案及本轮约定的内容已落实到目标文件。 |
| 核对与交付 | 75–100% | 七项通用指标均有达标依据，本轮交付完成。 |

阶段占比是统一的展示约定。根据区间内已明确事项或实际产物，以 5 个百分点为粒度估算，未完成时写“约”；百分比表示本轮初始化进展，不代表耗时比例或知识覆盖率。没有新增结论或产物时保持不变，不按对话轮数递增。范围改变或发现缺口时重新评估，可以回退并说明原因。

使用简短格式，例如：

```text
Wiki 初始化：约 20%｜当前：明确用途与边界
已明确：用途、读者基础、资料来源分工。
下一步：确定内容边界，再讨论原件与转录的保存形式。
```

按实际情况填写，不能照抄示例进度。仅讨论或模拟时标明范围，不因结束对话而显示 100%。无需另建进度或评估文件。

### 1. 读取现状，明确意图

查看目标中已有的项目说明、SELF、Agent 约定、来源和知识页面规范。只补读有助于当前判断的资料；已有 Wiki 先了解有效内容及组织方式。

将主题与用途、使用者与基础、内容边界、资料来源作为内部需要弄清的范围，先整理已有信息，不要求用户一次说全。每轮优先问一两个相关问题，每题给 2–4 个简短选项，说明单选或可多选；有依据时标出推荐项并用一句话说明理由。允许用户组合、修改、自由补充或表示不确定。名称、路径等具体信息可以直接问，不硬凑选项。

用户只说要建 Wiki 时，从容易回答的实际任务开始。例如：

> 你希望这个 Wiki 最先帮你完成哪类事情？可以多选或补充。
>
> - A. 系统学习一个主题，弄懂概念与联系。
> - B. 分析、评价或比较具体对象，形成有依据的判断。
> - C. 为项目或创作积累可复用的知识。

收到回答后，按下面的过程继续，直到影响定位的关键缺口得到解决：

1. **更新当前理解。** 从回答中提取已说明的目标、背景与限制，区分用户结论、自己的推测和未知信息。回答与原理解不符时先修正判断。
2. **选择下一轮问题。** 找出最影响用途、边界或方案的缺口，每轮只问一小组相关问题。根据上一轮回答继续展开，已明确的信息直接复用。
3. **先举例、给建议，再追问。** 用户说“不知道”“都行”，或只给出“想学习”等宽泛回答时，提供具体场景或可选方向，并说明自己的推荐理由。例如，用“看懂基础概念、比较两种方法、完成一个小项目”等预期结果帮助用户选择，再用选项追问所选方向需要的基础、资料或限制。让用户选择、纠正或补充，不仅重复原来的抽象问题。
4. **复述并核对理解。** 简述“目前理解你想……”，用一个具体使用场景及预期结果请用户核对。仍有重要偏差或缺口时，回到下一轮提问；保存形式、目录和检查项的讨论也沿用这个过程。

不要替用户补写答案，也不要把自己的例子或建议当作已确认需求。“不知道”或“都行”不足以证明需求已清楚；用户明确将某项选择交给你时，说明推荐理由并在授权范围内推进，其他关键缺口继续澄清。

围绕主要任务确认核心范围、相关主题的涉及程度和范围外内容，结合读者基础与代表性问题确定解释深度。保留来源陈述、整理者解释和实际核验的区别。

进入方案阶段前，应能依据已有信息和用户认可的具体场景，说明目标位置、主要用途、使用者与基础、初步内容边界及来源情况。暂时没有资料可以作为明确现状。重要缺口尚未解决时继续讨论，先解决缺口再写入受影响的定制内容；已有信息充分时直接推进，不为凑轮数重复提问。

### 2. 提出并确定方案与验收要求

给出简短的推荐方案，说明用途与范围、来源和知识的组织方式、必要的工作约定、本次会完成哪些内容，以及是否处理初始资料。解释理由和重要取舍，根据用户反馈修正，保留用户明确选择。

在用途与边界清楚后，按以下顺序逐项给出方案，沿用第 1 步的选择题与多轮澄清方式。各环节内的后续问题随回答调整；用户难以判断时先给例子、候选方案和推荐理由，已有结论直接复用：

1. **确定 raw 来源与保存。** 主动询问并推荐资料的取得渠道、材料类型和保存形式。先给“用户提供文件或链接”“AI 检索公开资料”“两者结合”等适用选项，再按主题推荐文章、论文、书籍、视频、音频、代码等相关类型。需要 AI 补充时，检索并推荐具体网站、教材、课程或作者资料等来源。用户没有资料或不知道怎么选时，给出少量适合当前用途的候选与推荐理由并继续讨论，不以“没有现成资料”结束来源讨论。

   为选定类型给出具体保存方案和一个示例条目。网页或 PDF 可保存实际取得的副本，并转成忠实的 Markdown；音视频保存实际取得的原文件，根据内容和现有能力确定字幕、转写等转录形式。说明能取得和转录的范围，受限或缺失部分如实记录，不把链接、摘要说成完整原件与转录。与用户确定方案及 AI 检索补充范围。每条仍只保留原件、`article.md` 和 `README.md`，按入库日期放在 `raw/YYYY-MM-DD/条目名称/`。
2. **推荐整体文件夹设计。** 结合已明确用途和资料形式检索相关材料，优先读取原始来源或官方资料。给出覆盖目标根目录、`raw/`、`wiki/` 和实际使用的 Skill 入口的简短目录树，说明项目 README、AGENTS、SELF、INDEX 及各内容目录的职责，区分已有结构与建议新增部分。说明推荐理由，请用户对分类、命名和查找方式提出建议；有重要取舍时提供少量可选设计。没有可用检索结果时说明限制，区分已有依据与建议。
3. **推荐 Wiki 页面内容与关系。** 目录方向确定后列出候选页面，并选 2–3 个代表性页面给出简短提纲或正文样例。说明各页解决的问题、读者需要的解释深度、例子与来源怎样呈现、从哪个入口进入、有哪些前置和关联页面。用选项请用户调整写法并接收补充建议，不以目录名称确认代替页面讨论。候选页面是计划，有实际正文后再创建并加入 INDEX。
4. **确定检查项。** 根据刚确定的 raw、Wiki 约定推荐具体检查。raw 只查保存位置、三部分齐全且可读、来源说明清楚，不默认逐段校对转录；Wiki 覆盖内容质量、依据与引用、链接与导航、目录组织、一致性与更新、当前状态与知识缺口。说明工具核对结构、AI 阅读并回查来源的分工，与用户确认后保存。
5. **确定工作方式与交付。** 明确入库、查询、审核的输入、输出和写回方式、本轮是否处理初始资料、验收要求及下一步。查看实际 Skill 文件，预留设计入口不作为可执行能力。

依据第 4 步的七项通用指标明确本轮验收要求，并按用途补充知识质量要求。用代表性任务检验预期结果，用范围内、范围外及边界案例检验收录与解释要求。优先使用用户的问题和资料；缺少资料时构造案例，并明确说明案例和推演的性质。

发现重要歧义时继续讨论并调整约定。边界需要扩展时，说明对用途、内容和工作方式的影响，按用户明确选择调整。已有资料可用于判断组织方式；是否保存、解读或写成知识页面，按本次明确的需求处理。

用途、边界、组织方式、知识要求和操作约定足以指导工作，且重要未决问题解决后，进入定制并更新百分比进度。复用已完成的阶段，在方案明确后自主完成授权范围内的普通实现细节。

### 3. 定制目标文件

按已确定的方案准备和定制文件。新目录带入所需的模板管理文件、本 Skill 的 README 和 SKILL，以及实际启用的 Skill 与依赖；已有 Wiki 保留有效内容，补齐缺失文件并调整受方案影响的部分。

结合各文件的职责完成定制：

- [项目 README](../../../README.md)：说明用户自己的 Wiki 和使用入口。
- [AGENTS](../../../AGENTS.md)：引用目标实际存在的规范与可用 Skill，落实操作及写回约定。
- [raw 规则](../../../raw/README.md)：记录确认的来源渠道与类型、原件与转录形式、入库日期路径、三部分结构、来源说明和基础检查要求。
- [知识页面规范](../../../wiki/README.md)：记录确认的目录与页面职责、页面写法与关系、读者基础、解释深度，以及证据、维护和检查要求。
- [SELF](../../../wiki/SELF.md)：写明服务对象、用途、内容边界、实际已有内容、缺口和下一步。
- [INDEX](../../../wiki/INDEX.md)：连接已有管理入口和实际知识页面，按内容组织阅读路径。

模板其他管理文件按实际需要保留。带入 Skill 时保留执行所需文件及设计说明；携带预留设计时标明状态。知识分类根据需求与实际内容建立，所有文件引用以目标中的实际文件为准。

没有初始资料时，SELF 如实说明现状。用户明确要求处理初始资料、写入知识或增加 Skill 时，按相应需求与项目约定完成；创建或修改 Skill 使用本项目 [skill-creator](../skill-creator/SKILL.md)。

保留目标已有的 Git 历史与远程配置，初始化不向模板仓库推送用户内容。用户要求配置或发布自己的仓库时，按该项明确请求处理。

已确定的约定落实到目标文件，README 已适应该用户，SELF 和导航反映实际内容后，进入核对。

### 4. 依据评估指标核对并交付

读取定制后的文件，对照已确定方案逐项核对以下指标，并为每项结论指出对应文件、检查结果或案例判断：

| 指标 | 核对动作与达标条件 |
| --- | --- |
| 用途可执行 | 从定位说明中指出服务对象、主要任务和预期结果，用用户认可的具体场景及代表性问题说明怎样的知识或回答对用户有用。 |
| 范围可判定 | 依据已保存的核心范围、相关主题的涉及程度及范围之外的内容，说明范围内、范围外及边界案例的判断理由；重要歧义已解决。 |
| 深度有依据 | 从知识页面规范中指出读者基础、主要页面要解释的内容和深度，用代表性任务检验要求是否足以支撑用途。 |
| 证据规则可执行 | 检查来源保存、引用与追溯约定，用一份来源或构造案例说明如何区分来源陈述、整理者解释和实际核验。 |
| 操作约定可执行 | 对照 Agent 约定及实际 Skill 文件，用典型任务说明入库、查询、审核的输入、输出与写回方式，可用与预留能力状态准确。 |
| 文件落实一致 | 对照方案与修改前内容，检查文件职责、链接及 INDEX，确认约定已落实、引用有效、原有内容及 Git 配置得到保留。 |
| 后续工作可接续 | 仅依据已保存的 SELF、说明与使用入口，说明当前内容、缺口、下一项任务、所需输入和预期产物。 |

同时核对 raw 来源与保存形式、Wiki 目录与页面职责、检查项是否按讨论结论写入对应规范。已有知识页面是否满足这些要求，按实际核验另行说明。

逐项记录结论、依据、缺口及下一步，使用以下状态：

- **达标**：满足验收条件，有可定位的文件或检查证据。
- **待补齐**：约定缺失或不完整，尚不足以指导工作。
- **未验证**：相关约定已形成，达标所需检查尚未完成。

文件检查、场景推演与真实运行分别说明。没有资料时可以用构造案例推演规则；不能把推演写成知识质量或实际运行已经通过。

发现定位或边界缺口时返回讨论；发现约定遗漏或链接错误时在范围内修正并复查。需要改变用途或范围的重要问题与用户商量。未完成必要检查的指标标记“未验证”，不提前宣布整个初始化完成。

七项指标均有达标依据，影响用途、范围、知识要求和操作方式的关键缺口已解决，且本轮约定的交付已完成后，显示 100% 并宣布本轮初始化完成。后续知识建设可以保留待办，知识覆盖、内容质量和实际运行结果按实际检查另行说明。

交付目标位置、主要定制结果、使用入口、逐项评估及下一步，依据实际完成情况更新阶段状态。

## 输出

每轮讨论先显示百分比与当前环节，再简述已确认事项和关键缺口，优先以带例子、推荐理由的选择题继续澄清。按顺序给出来源与保存建议、整体目录树、代表性页面提纲或样例、检查与工作约定，逐步明确本轮验收要求。实施后交付定制后的 Wiki、目标位置、主要变化、使用入口，以及每项指标的结论、依据、缺口和下一步。

初始化完成依据第 4 步的验收结果。用户和后续 Agent 能理解用途、边界、知识要求、工作方式、实际内容与下一步。没有资料时仍可完成结构与约定的初始化；已有知识的覆盖、质量和实际运行结果单独说明。

## 校验

交付前按实际范围核对：

- [ ] 用途、边界、知识要求与操作方式明确，影响判断的重要缺口已解决。
