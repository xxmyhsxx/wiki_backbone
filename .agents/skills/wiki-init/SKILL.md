# Wiki Init

## 任务

基于通用模板完成用户自己的 Wiki 初始化。交付后，用户和新进入的 Agent 能从文件中理解 Wiki 的目的、范围、实际已有内容、工作方式和下一步。

本 Skill 的当前设计见 [README](README.md)。执行所需的动作与判断写在本文件中；初始化使用同一项目中的模板管理文件。

## 输入

结合对话和目标目录取得：目标位置、用途与主题、内容范围、希望怎样使用知识，以及已有资料与文件。按实际需要补充读者基础、资料类型、关注问题和维护偏好。

用户在模板副本中要求初始化当前 Wiki 时，以该副本为目标；要求创建到其他位置时，明确目标目录。能从已有内容判断的信息先读取，不重复询问。没有初始资料时仍可完成结构与约定的初始化。

## 原则

1. **围绕使用意图提问。** 根据实际场景和代表性问题澄清会影响方案的缺口，问题随回答逐步展开。
2. **主动分析与推荐。** Agent 先提出判断、理由和重要取舍，帮助用户选择组织方式；普通实现细节自主决定。
3. **复用已明确的信息与授权。** 方案已经明确时继续范围内的定制与核对，不重走已完成的讨论。用户仅要求讨论时交付分析与方案。
4. **进度反映实际状态。** 在关键进展或方向变化时展示当前阶段、已确定事项和待讨论问题，实际完成后再更新状态。
5. **保护与复用已有内容。** 修改前读取目标文件，只调整方案影响的内容，保留有效约定、资料、知识和 Git 配置。复制模板管理文件时不复制 `.git/`，不改写原始证据。
6. **范围与内容如实记录。** 计划、已保存资料、已形成知识和实际核验分别说明；导航指向实际文件，知识分类按需要和内容建立。

## 工作步骤

### 1. 读取现状，明确意图

查看目标中已有的项目说明、SELF、Agent 约定、来源和知识页面规范。只补读有助于当前判断的资料；已有 Wiki 先了解有效内容及组织方式。

整理当前已经明确的用途、范围和已有情况，再询问会改变方案的缺口。用户只说要建 Wiki 时，可从下面的问题开始：

> 你希望这个 Wiki 最先帮你完成什么事？可以举一个以后会向它提出的问题。

例如，用户希望整理论文，再按需要区分学习概念、比较方法或记录实验等用途。已有信息充分时直接进入方案设计，不要求用户填写固定问卷。

目标位置或影响用途与范围的重要问题尚未明确时，继续可判断的讨论，先解决缺口再写入受影响的定制内容。

### 2. 提出并确定方案

给出简短的推荐方案，说明用途与范围、来源和知识的组织方式、必要的工作约定、本次会完成哪些内容，以及是否处理初始资料。解释理由和重要取舍，根据用户反馈修正，保留用户明确选择。

已有资料可以用于判断组织方式；是否保存、解读或写成知识页面，按本次明确的需求处理。查看目标实际可用的 Skill，预留设计入口不作为可执行能力。

用阶段状态展示进展。例如：

```text
Wiki 初始化进度
✓ 明确用途与范围
→ 确定组织方式与工作约定
○ 定制文件
○ 核对与交付
```

根据实际工作选择当前状态，可以补充已确定与待讨论事项。示例的勾选不是默认完成情况；不编造百分比，不额外创建进度文件。复用已完成的阶段，在方案明确后自主完成授权范围内的普通实现细节。

### 3. 定制目标文件

按已确定的方案准备和定制文件。新目录带入所需的模板管理文件、本 Skill 的 README 和 SKILL，以及实际启用的 Skill 与依赖；已有 Wiki 保留有效内容，补齐缺失文件并调整受方案影响的部分。

结合各文件的职责完成定制：

- [项目 README](../../../README.md)：说明用户自己的 Wiki 和使用入口。
- [AGENTS](../../../AGENTS.md)：引用目标实际存在的规范与可用 Skill。
- [raw 规则](../../../raw/README.md)：按资料类型明确保存、版本和追溯方式。
- [知识页面规范](../../../wiki/README.md)：按知识组织方式明确页面、解释、引用和维护要求。
- [SELF](../../../wiki/SELF.md)：写明服务对象、用途、范围、实际已有内容、缺口和下一步。
- [INDEX](../../../wiki/INDEX.md)：连接已有管理入口和实际知识页面，按内容组织阅读路径。

模板其他管理文件按实际需要保留。带入 Skill 时保留执行所需文件及设计说明；携带预留设计时标明状态。知识分类根据需求与实际内容建立，所有文件引用以目标中的实际文件为准。

没有初始资料时，SELF 如实说明现状。用户明确要求处理初始资料、写入知识或增加 Skill 时，按相应需求与项目约定完成；创建或修改 Skill 使用本项目 [skill-creator](../skill-creator/SKILL.md)。

保留目标已有的 Git 历史与远程配置，初始化不向模板仓库推送用户内容。用户要求配置或发布自己的仓库时，按该项明确请求处理。

### 4. 核对并交付

对照方案检查用途、范围、工作约定和实际组织是否一致。确认 README 已适应该用户，SELF 如实记录内容与下一步，INDEX 和页面链接指向真实内容。

修正范围内的文件、描述与链接问题，确认原有内容和 Git 配置得到保留。需要改变用途或范围的重要问题重新讨论；关键目标尚未确定时，说明实际完成部分与待完成内容。

交付目标位置、主要定制结果、使用入口、检查范围、必要遗留问题和下一步。依据实际完成情况更新阶段状态。

## 输出

讨论阶段提供意图理解、推荐方案、必要问题与进度。实施后交付定制后的 Wiki、目标位置、主要变化、使用入口和实际核对结果。

结构与约定的初始化完成时，用户和后续 Agent 能理解用途、范围、组织方式、实际已有内容与下一步。知识覆盖和核验程度单独说明；没有资料不影响结构初始化完成。

## 校验

交付前按实际范围核对：

- [ ] 用途、范围与组织方式已明确，重要未决问题如实说明。
- [ ] README 介绍用户自己的 Wiki；SELF 区分实际内容、计划与核验状态。
- [ ] AGENTS、来源规则、知识页面规范与已确定方案一致，可用和预留 Skill 分别说明。
- [ ] 文件、Markdown 链接和 INDEX 对应实际目标，用户原有内容与 Git 配置得到保留。
- [ ] 进度及完成声明反映实际工作，知识建设与结构初始化分别说明。
- [ ] 交付已核对的范围、未验证部分和具体下一步；格式检查、场景推演与真实初始化结果分别说明。
