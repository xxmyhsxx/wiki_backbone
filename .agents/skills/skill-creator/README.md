# Skill Creator

## 1. 任务与设计目标

创建或修改完整的 Skill，让执行者知道要解决什么问题、采用什么方法、依据什么判断结果。先理解任务并讨论设计，再按授权写入和实现，最后检查设计与执行是否一致。

README 保存当前设计及关键取舍，SKILL.md 保存执行动作与判断；可选的 references 保存具体步骤需要的辅助材料。设计目标必须落实到执行方法，不能只换个标题重复一遍，也不能依赖未交付的对话结论。

## 2. 使用边界

适用于新建 Skill、修改已有 Skill，或把任务方法整理成 Skill。局部修改只分析本次变化及其影响，复用其余已确认设计，不擅自裁决无法解释的设计与实现冲突。

讨论、写入 README 和实现 Skill 分别判断授权。设计变化先讨论，经授权写入 README；当前 README 完成且用户确认实现后，再修改 SKILL 或辅助材料。已获得的有效授权不重复询问，用户明确要求以其指定方式完成时遵从。

仅修正实现以符合已确认设计，或调整不影响设计的文字时，用户对该修正的明确指令即对应范围的修改授权，无需重写 README 或重走设计流程。

## 3. 输入设计

根据需求和已有材料判断目标、交付物及当前阶段。修改时读取 README、SKILL 和本次涉及的辅助材料，保留用户已有修改。

README 与实现存在差异时，区分本轮待同步的设计、用户已授权的实现修正和无法解释的冲突。前两者按对应授权继续；冲突先说明差异并询问。缺少 README 时，从现有实现提出待确认的设计理解，不能把反推结果当作已确认设计。

## 4. 原则设计

- 主动分析目标、关键问题、质量依据和候选方法，再讨论会改变目标、范围、成本或流程的选择；不让用户填写固定问卷。
- 分析到足以确定关键动作、判断与检查方法即可。能合理量化时量化，依据不足时采用可观察的定性判断，不编造阈值。
- 原则保存全程约束，步骤规定具体操作；必需方法写入 SKILL 或明确引用的随包材料，references 按需读取。
- 用具体对象和动作表达，保留必要条件、例外、依据和不确定性。合并重复要求，不为固定篇幅或章节凑内容。
- 优先调整、合并或删除已有内容，不为假设需求增加规则、文件、状态记录或评测系统。

## 5. 工作流程设计

1. **确定现状与阶段。** 从尚未完成的部分继续，区分需要讨论、等待写入、等待实现和已授权修正。
2. **理解任务并提出设计。** 说明关键问题为什么影响结果、方法何时采用、质量依据什么判断。先给候选方案和理由，只询问会影响选择的真实缺口。
3. **确定设计。** 核对边界、输入、原则、步骤、输出、辅助材料及校验是否足以指导执行，不强制逐项提问或建立映射表。
4. **按授权写入 README。** 只记录当前设计及必要理由，不记无关讨论历史。写入后依据已有授权判断是否可以实现，缺少实现授权时请用户确认当前版本。
5. **实现完整 Skill。** 将设计转成动作、判断和必要分支；按实际需要处理辅助材料，在使用它们的步骤中说明何时读取及怎样使用。
6. **检查并交付。** 核对设计一致性、执行衔接、表达、元数据和引用，再对变更涉及的代表性场景做检查。需要改变已确认设计时先说明取舍。

例如，算子开发的正确性要求可以落实为：按约定输入与数据类型和参考实现比较，每轮优化先核对正确性，再比较性能。这个例子说明方法应怎样影响操作，不要求其他任务照搬。

## 6. 输出设计

README 默认结构：任务与设计目标、使用边界、输入设计、原则设计、工作流程设计、输出设计、References 设计（可选）、校验设计和文件结构。保留有用结构，没有实际内容的可选部分不填充。

SKILL 默认结构：YAML frontmatter，以及任务、输入、原则、工作步骤、输出和校验。步骤依据任务组织，不要求每步填写相同字段。

`name` 与目录名一致，使用 1–64 个小写英文字母、数字或连字符，不能以连字符开头或结尾，也不能有连续连字符。`description` 为 1–1024 字符的非空字符串，说明用途和使用时机。不强制其他元数据；另有已确认的平台要求时遵从。格式依据为 Agent Skills Specification（`https://agentskills.io/specification`）。

讨论阶段交付方案与必要问题；README 阶段交付设计；实现阶段交付 SKILL 及所需辅助材料。说明实际改动、检查结果和未验证部分，不默认新增计划或报告文件。

## 7. References 设计

本 Skill 不预设 references。只有材料需要独立维护、且具体步骤会使用时才增加；执行必需的内容随 Skill 交付。

## 8. 校验设计

静态检查覆盖授权范围、设计与实现一致性、方法是否可执行、步骤衔接、元数据、占位符与文件引用。逐段检查表达：删除不影响理解、判断或行动的内容，改清需要猜测的对象、动作和指代；保留会影响执行的条件与例外。

按改动选择代表性场景：模糊需求、仅认可方案、只授权 README、确认后续接实现、局部修正、缺少 README 或设计与实现冲突。不要求每轮全部重跑。优先使用用户材料，构造案例明确标注。

检查应指出对应规则与实际结果。静态检查和场景推演不冒充真实运行；条件和授权允许时再做实际执行。README 阶段只检查设计，不为消除待同步差异提前改实现。

## 9. 文件结构

```text
skill-creator/
├── README.md
└── SKILL.md
```

创建的其他 Skill 同样以这两个文件为基础，辅助材料按需增加。
