# Wiki Review

当前设计由 [SKILL.md](SKILL.md) 执行。

## 1. 任务与设计目标

审核指定范围内的知识、证据、解释深度、关联和组织，交付可定位、有依据的发现与修改建议。获得修复要求时完成范围内修复及复查。

| 关键问题 | 影响 | 采用的方法与质量依据 |
| --- | --- | --- |
| 机械检查与内容核验混淆 | 链接正确仍可能存在错误主张或解释断点。 | 复用 lint 结构检查，另行阅读正文和关键来源，分别报告证据层次。 |
| 审核者靠知识补齐页面 | 页面看似完整，读者却无法理解主线。 | 沿读者路径检查实际解释和链接承接，定位缺失机制、前提或关系。 |
| 差异被误报为矛盾 | 版本、对象和条件可能合理不同。 | 对齐定义、版本、条件与来源，再确认冲突或保留分歧。 |
| 缺口与建议没有依据 | 容易扩大范围或删除仍有价值的内容。 | 定向查找候选正文，说明缺口的用途、范围、承接位置及影响。 |

## 2. 使用边界

用户要求审核、评估质量、核验主张或检查维护问题时使用。仅机械检查使用 [wiki-lint](../wiki-lint/SKILL.md)。默认交付发现；用户明确要求修复时在对应范围完成，不自动将报告扩展为重构或新研究。

审核初始化约定时采用 [wiki-init](../wiki-init/SKILL.md) 的指标；审核知识页面时采用该 Wiki 的读者基础与知识质量要求。范围较大时说明覆盖方式，未读取部分保持未核验。

## 3. 输入设计

输入包括目标 Wiki、指定页面或问题、重点与修复范围。先读 SELF、相关规范和目标正文，从具体主张定向回查来源；不把全部 raw 当作默认前置阅读。

来源记录按当前项目实际格式读取，不要求固定 YAML 字段、论文页面类型或独立来源登记文件。

## 4. 原则设计

1. 已确认发现来自正文与证据，候选疑点和未核验内容分别说明。
2. 解释深度依据读者与页面职责，篇幅、标题数及链接数量不作为充分质量证明。
3. 检查结论与实际覆盖相称，抽样审核不宣称全库已经正确。
4. 合并、压缩或删除建议保留独特机制、条件、反例、证据及阅读联系。
5. 直接修复按用户要求执行，普通范围内修正自主完成；重要取舍先说明影响。

## 5. 工作流程设计

1. **确定范围与标准。** 读取相关规范和正文，明确页面职责、重要主张、核心解释路径和实际覆盖方式。
2. **机械核对。** 需要结构检查时使用 [wiki-lint](../wiki-lint/SKILL.md) 的脚本。局部检查说明范围及跳过的全局可达性检查。
3. **核验关键主张。** 对核心结论、数字、公式、重要归因和比较回查实际来源，保留对象、版本与条件，区分登记有效、来源支持和真实运行。
4. **检查解释与一致性。** 沿正文和链接检查机制、步骤、前提及限制是否承接读者需求，对齐跨页对象与条件后判断矛盾或过时结论。
5. **判断知识缺口。** 从任务需要提出具体缺口，定向搜索并读取候选；说明查找范围、现有承接及需要补什么，不凭缺少链接就断言全库缺失。
6. **交付与复查。** 发现给出位置、问题、依据、影响及最小建议。按授权修复后回查受影响内容，复跑必要机械检查并维护导航与实质变化后的 SELF。

## 6. 输出设计

报告实际范围和方法、已确认发现、证据不足或待核内容、关键缺口，以及修复结果。无已确认问题时说明实际检查过什么及仍未覆盖什么。

| 评估项 | 完成条件与证据 |
| --- | --- |
| 覆盖透明 | 阅读范围、来源回查与抽样方式明确，未核验部分可辨识。 |
| 发现有依据 | 每项确认问题可定位到实际正文与证据，来源不可得没有被直接判为事实错误。 |
| 深度与关联可判断 | 核心解释路径和必要链接经过读取，缺口与分歧的影响具体说明。 |
| 修复可核对 | 建议保留知识价值，已修复内容、剩余问题和实际复查结果明确。 |

完成审核表示已完成约定范围的检查与报告；存在未修复问题不影响报告完成，但需要明确说明。修复完成另按实际改动与复查判断。

## 7. References 设计

机械检查复用兄弟 [wiki-lint 脚本](../wiki-lint/scripts/check_wiki.py)，不另建同功能工具。内容审核依据目标规范、正文和实际来源。

维护时检查矛盾、过时内容与知识缺口的思路参考 [Karpathy 原始说明](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)。本模板将其内容判断交给 review，机械检查交给 lint。

## 8. 校验设计

检查设计与执行一致，并推演机械检查通过但正文有误、来源不可读、条件差异、解释断点、范围受限和已授权修复等场景。静态检查、来源核验与真实运行结果分别说明。
