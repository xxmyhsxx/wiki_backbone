# Wiki Query

当前设计由 [SKILL.md](SKILL.md) 执行。

## 1. 任务与设计目标

依据 Wiki 的实际内容帮助用户定位、理解、比较或分析问题，交付带依据的结果，说明知识覆盖及核验边界。

| 关键问题 | 影响 | 采用的方法与质量依据 |
| --- | --- | --- |
| 查询意图不同 | 定位、解释和比较需要不同产物。 | 根据请求确定交付，已有意图明确时直接处理。 |
| 索引与术语命中不足以支撑回答 | 容易误报覆盖或依赖模型记忆补齐。 | 搜索后读取正文及关键关联，结论对应实际读取位置。 |
| 多页结论有条件差异 | 简单拼接可能形成错误比较。 | 对齐对象、定义、版本和条件，分开说明共同结论、分歧与新分析。 |
| 对话结果值得保留 | 查询产生的知识可能无法复用。 | 指出可保存的增量；用户要求保存时按入库与维护规范写回。 |

## 2. 使用边界

用户要求查找、解释、比较或基于 Wiki 分析时使用。默认交付查询结果；用户要求保存或修改时完成对应写回，不因一次查询自动改动 Wiki。

新增来源并整合使用 [wiki-ingest](../wiki-ingest/SKILL.md)，系统审核使用 [wiki-review](../wiki-review/SKILL.md)。外部检索依据用户请求与 Wiki 约定，区分 Wiki 已有知识和新查材料。

## 3. 输入设计

取得问题、目标 Wiki、所需输出及用户指定的来源或时间范围。结合 SELF 和 INDEX 理解用途、读者基础及现有入口；仅补问会改变问题或结果的重要缺口。

## 4. 原则设计

1. 先定位再读取，以正文支持回答；访问失败不代表 Wiki 没有该知识。
2. 回答使用可定位的页面与必要来源，区分页面陈述、新推导和实际核验。
3. 比较时保留对象与条件，缺乏可比证据时说明限制。
4. 新材料与写回按实际授权处理，复用已经明确的范围。
5. 结果长度和形式服从问题，缺口与后续建议具体说明。

## 5. 工作流程设计

1. **理解问题。** 确定用户需要位置、解释、比较还是分析，明确问题边界及预期结果。
2. **定位并读取。** 从索引与定向搜索取得候选，以名称、别名和机制补查，读取正文及必要前置和相邻页面。
3. **组织回答。** 对齐问题与证据，说明依据、条件、分歧和未核验部分。用户仅要位置时交付入口及它承担什么内容。
4. **处理缺口与新材料。** 说明查找范围、不可读内容及实际缺口；按明确请求检索外部材料，新的来源与解释分别标明。
5. **交付或写回。** 有依据且已有页面未表达的跨页联系、补足可比条件的比较或澄清分歧的整理，可以说明保存价值和建议落点。简单查找、重复解释或只换一种说法通常不主动建议另建页；缺乏依据的推测先说明缺口，不当作已确认知识。

   这些判断只用于主动保存建议。未请求保存时交付答案及可选的具体建议；用户明确要求保存时，包括简单查询结果，按请求范围写回。遵循已确认的目录与页面职责，优先复用既有页面；新增来源按 raw 三部分与入库日期约定保存，已有归档保持原位置。维护导航和必要 SELF，使用 [wiki-lint](../wiki-lint/SKILL.md) 核对受影响的条目、页面及关联，复用仍有效的内容核验结果。

## 6. 输出设计

交付与问题相称的位置、解释、比较表或分析，并就近引用实际文件或来源。必要时说明检索范围与限制；不强制创建查询日志或分析页。

| 评估项 | 完成条件与证据 |
| --- | --- |
| 回答承接问题 | 结果覆盖所需任务，定位结果说明内容作用，比较保留共同维度与条件。 |
| 依据可回查 | 实质结论对应已读正文或明确标注的新分析，重要来源定位真实。 |
| 边界准确 | 未找到、不可读、证据冲突及未核验分别说明，外部新材料未被冒充已有知识。 |
| 写回与请求一致 | 普通查询不产生未请求的写入；要求保存时实际内容、引用与导航已核对。 |

找到的材料不足以回答核心问题时，交付可支持的部分和具体缺口，不宣称问题已经解决。

## 7. References 设计

复用目标 Wiki 的入口、规范和实际正文；需要写回时复用入库与 lint 能力。

带引用的查询与可复用分析思路参考 [Karpathy 原始说明](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)；其实现方式可对照 [karpathy-llm-wiki](https://github.com/wpzero/karpathy-llm-wiki)。具体写回范围采用本项目的任务约定。

## 8. 校验设计

检查定位与回答边界、引用及写回条件，并推演已有知识充分、术语不同、证据冲突、查找受限、需要外部材料和要求保存等场景。保存建议重点核对有依据的新综合、简单查找未请求保存、用户明确要求保存简单结果、缺乏依据的推测；价值判断不代替用户的写回请求。推演与真实查询结果分别说明。
