# Wiki Query

## 任务

用实际读取的 Wiki 内容承接用户问题，交付可回查的结果，并说明覆盖与核验边界。当前设计见 [README](README.md)。

## 输入

取得问题、目标 Wiki、需要的输出及指定来源或时间范围。结合 SELF、INDEX 和实际规范理解用途与读者基础；只补问会改变问题或结果的重要缺口。

## 原则

1. 先定位再读取，正文及实际来源支持结论，访问失败不代表知识不存在。
2. 区分页面陈述、新分析和实际核验，重要结论保留可定位依据。
3. 比较保留对象、定义、版本与条件，证据不足时说明可支持的范围。
4. 普通查询交付结果；用户要求保存或修改时在对应范围完成写回。
5. 外部检索按请求与 Wiki 约定处理，新查材料与已有知识分别说明。

## 工作步骤

### 1. 理解问题与交付

判断用户需要位置、解释、比较还是分析，明确关注的对象、范围与结果。已有意图充分时直接工作，不重复询问。涉及多个问题时围绕主要用途组织回答。

### 2. 定位并读取正文

从 INDEX 和定向搜索定位候选，用名称、别名和机制补查。读取能够承接问题的正文及必要前置、相邻页面，确认引用位置实际存在并提供所需内容。

命中同一术语不足以证明覆盖。未找到时说明实际查找范围；不可读或检索失败的候选保留未核实，不用模型记忆补写为 Wiki 事实。

### 3. 形成有依据的结果

定位任务交付入口及它承担什么解释。解释与分析任务按问题组织正文，就近引用实际文件或来源；将新推导、构造例子与页面已有结论分别标明。

比较时对齐对象、定义、版本、评价维度与条件。能够共同支持的结论、条件差异和未解决的分歧分别说明；没有可比证据时保留限制。

关键结论需要核验或页面依据不足时，定向回查实际来源，说明核对范围。只读取正文不能报告实验或运行通过。

### 4. 处理缺口与新材料

说明问题未被承接的具体部分，是解释不足、来源不足、条件冲突还是查找受限。提出与用途有关的下一步及建议落点。

用户要求外部检索时查找并读取可靠来源；其他情形按 Wiki 已明确约定处理。新增材料与已有 Wiki 知识分别引用；需要整合新来源时使用 [wiki-ingest](../wiki-ingest/SKILL.md)。

### 5. 交付或按要求写回

根据问题交付位置、解释、比较表或分析。值得保存的增量可说明保存价值与位置；用户已要求保存时直接复用对应页面、来源与知识规范写回，不重复请求已明确的授权。

按已确认的目录与页面职责选择落点，优先补充已有页面。新增来源按 raw 的入库日期与原件、转录文章、说明三部分约定保存；复用已有归档时保持原位置。

写回后读取实际内容，核对依据、条件和必要关联，维护 INDEX 及实质变化后的 SELF，使用 [wiki-lint](../wiki-lint/SKILL.md) 检查受影响条目、页面及关联，复用仍有效的内容核验结果。重大范围或结构变化先与用户商量。

按以下条件判断结果：

| 评估项 | 完成条件与依据 |
| --- | --- |
| 回答承接问题 | 结果覆盖所需任务，位置说明作用，比较维度与条件明确。 |
| 依据可回查 | 实质结论对应已读正文或明确的新分析，重要来源定位真实。 |
| 边界准确 | 未找到、不可读、冲突及未核验分别说明，新材料未被当作已有知识。 |
| 写回与请求一致 | 实际写入范围与请求一致，要求保存的内容、引用和导航已核对。 |

材料不足以回答核心问题时交付可支持部分和具体缺口，不宣称问题已解决。

## 输出

交付与问题相称的结果和依据，必要时说明检索范围、核验限制及具体后续建议。已写回时提供实际位置及检查结果。没有保存请求时无需创建查询日志或知识页面。

## 校验

- [ ] 交付形式承接用户意图，重要结论有真实读取依据。
- [ ] 条件、差异、新分析及核验边界清楚，限制没有被当作知识缺失。
- [ ] 外部新材料与 Wiki 已有知识分别说明。
- [ ] 写回与请求相符，实际改动和必要引用、导航经过核对。
