# Wiki Ingest

当前设计由 [SKILL.md](SKILL.md) 执行。

## 1. 任务与设计目标

读取用户指定的来源，将有价值的知识增量整合到 Wiki。交付应形成可独立阅读的解释、可追溯的依据和有用的阅读联系，复用已经充分的内容。

| 关键问题 | 影响 | 采用的方法与质量依据 |
| --- | --- | --- |
| 材料不完整或版本不明 | 容易把摘要、提取稿或旧版本当作完整证据。 | 核对身份、版本及实际可读范围，结论与取得的材料相称。 |
| 搜到术语就认为已覆盖 | 可能遗漏机制与条件，也可能重复建页。 | 读取候选正文，按实际解释需求判断复用、补充、新建或暂缓。 |
| 只有来源摘要 | 知识无法独立使用，多份资料也没有形成联系。 | 按用途解释问题、机制或步骤、条件和证据，整合已有知识及分歧。 |
| 写入后未经核对 | 来源、链接与导航可能与正文不一致。 | 从实际入口复读，回查关键依据，再完成机械检查。 |

## 2. 使用边界

用户要求入库、解读并写入资料，或用新来源补充已有 Wiki 时使用。只要求讨论或拟稿时交付具体草稿及落点；仅查询使用 [wiki-query](../wiki-query/SKILL.md)，审核使用 [wiki-review](../wiki-review/SKILL.md)。

接受文本、网页、文档、图像、代码或其他实际可读取的来源。解析与视觉核对按材料需要调用已有能力，不承诺仅凭扩展名就能完整读取。初始化定位与范围尚缺关键约定时复用 [wiki-init](../wiki-init/SKILL.md) 澄清受影响部分。

## 3. 输入设计

输入包括目标 Wiki、来源、实际版本或获取信息、用户关注的问题和写入范围。先读 SELF、来源规则、知识页面规范及相关页面，复用已明确的读者基础和质量要求。

用户没有提供关注点时，Agent 根据用途提出重点。材料不可得或核心部分无法解析时，区分访问、解析与证据缺失，继续可可靠完成的部分。

## 4. 原则设计

1. 来源保存与知识解释分别处理，保留原件，不改写原始证据。
2. 正文读取支持覆盖判断，搜索命中与读取失败均不作为充分覆盖或缺失的证据。
3. 深度服从用途和解释责任，保留核心机制、步骤、前提和限制。
4. 复用有效内容，保留来源分歧和条件差异；同一来源重复入库应先检查已有版本与增量。
5. 已明确的写入范围自主完成，重要范围或结构变化先讨论。

## 5. 工作流程设计

1. **确认来源与目标。** 核对身份、版本、获取方式和可读范围，读取目标实际规范及相关入口。
2. **理解材料。** 建立问题、解释、条件与证据之间的关系，必要时查看原始图表、公式或代码；未实际运行的结果保持未验证。
3. **判断已有覆盖。** 按理解问题检索名称、别名和机制，读取候选正文及关联内容，区分充分、部分、相关、冲突与未核实。
4. **确定增量。** 说明补什么、为什么需要、来源在哪里、由哪里承接。新建内容应有独立作用；无新材料或真实缺口时可以不修改。
5. **整合并维护。** 按来源规则保存材料，按知识规范写入解释，维护必要链接、INDEX 和实质变化后的 SELF。
6. **核对实际产物。** 从读者路径复读，回查关键陈述与条件，使用 [wiki-lint](../wiki-lint/SKILL.md) 检查受影响文件。关键缺口未解决时说明部分结果。

## 6. 输出设计

交付实际新增或修订的知识、来源及必要关联；简要说明位置、复用内容、检查范围和未完成部分，不强制产生入库报告或固定数量页面。

| 评估项 | 完成条件与证据 |
| --- | --- |
| 来源可靠定位 | 实际使用材料、版本及可读范围明确，关键依据可回查。 |
| 增量有依据 | 覆盖判断来自正文，实际改动补足需求或澄清分歧，重复入库没有制造重复内容。 |
| 解释可独立使用 | 读者能沿正文及有效链接理解问题、关键机制或步骤、条件和证据边界。 |
| 维护与声明一致 | 必要引用、链接和导航已核对，实际写入、草稿及未核验部分分别说明。 |

无需修改时，实际复核已有内容充分也可以完成；材料核心部分不可读或关键解释仍断裂时交付部分结果。

## 7. References 设计

复用目标 Wiki 的规范和实际页面；机械检查复用兄弟 Skill 的脚本。本 Skill 不增加独立解析或检索工具。

LLM Wiki 的来源整合与持续修订思路参考 [Karpathy 原始说明](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)，具体流程依据本项目的用途与来源约定确定。

## 8. 校验设计

检查设计与执行一致、引用可定位，并推演新来源、重复来源、来源冲突、部分可读和只要求拟稿等场景。内容核验、机械检查和实际运行分别说明；脚本通过不代替解释与证据核验。
