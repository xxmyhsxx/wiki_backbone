# 示例的知识页面规范

本 Wiki 帮助首次使用模板、能够阅读 Markdown 的用户理解 LLM Wiki，并判断一次资料入库应当改变什么。当前画像见 [SELF](SELF.md)，阅读入口见 [INDEX](INDEX.md)。

## 范围与页面职责

核心范围是来源、知识与工作约定的职责，以及入库、查询和维护中的增量判断。开源项目中的具体规则作为有身份的实例，不扩成软件效果评测、检索系统设计或统一 Wiki schema。

| 页面 | 应当解决的问题 | 解释深度 |
| --- | --- | --- |
| `source-and-knowledge.md` | 为什么将来源、知识和工作约定分开？如何回查依据？ | 解释各层职责、从原文到知识的关系，以及保存资料与理解知识的区别。 |
| `ingest-and-maintenance.md` | 新资料应更新什么？何时无需改正文？如何处理关联和分歧？ | 解释阅读已有内容、判断归档/正文/引用增量、维护相关页的过程与具体例子。 |

两页之间通过带用途说明的链接承接前提与步骤。优先补充已有页面；有实际、独立的新问题时再讨论扩展，不为分类或页面数量创建空页。

## 表达与依据

知识页使用中文，开头说明讨论的问题与用途，按解释需要组织正文。定义、步骤、条件和例子应足以供初次使用者独立阅读，不机械填充统一标题。

关键陈述附近使用标准 Markdown 相对链接指向实际来源条目的说明或原件，并给出可辨认的标题、段落或规则位置。文件名包含扩展名；引用来源说明时，说明中应能继续到达所用版本的原件。

分别标明 Karpathy 的模式描述、Astro-Han 的项目设计、整理者的解释或例子，以及本示例的实际操作结果。两份文档不能证明所有 LLM Wiki 的效果；具体项目的目录、状态块和工具选择不写成通用必要条件。条件与结论一同保留，来源不同先对齐定义、对象、版本和条件再判断分歧。

原件与忠实英文转录按照 [raw 规则](../raw/README.md) 保存。正文不改写原始证据，也不用中文摘要充当原件。

## 维护与检查

核心定义、条件或结论变化时，搜索名称、别名与相关表述，读取命中的直接关联页，只更新确实受影响的内容。新增、移动或合并知识页时同步链接和 INDEX；实际覆盖或下一步变化时更新 SELF。INDEX 只指向实际页面，SELF 区分已有内容、缺口和未验证场景。

综合检查复用仓库 [wiki-lint](../../../.agents/skills/wiki-lint/SKILL.md)，内容审核复用 [wiki-review](../../../.agents/skills/wiki-review/SKILL.md)：

- 内容质量：两页职责清楚，关键解释、前提和例子能承接本示例用途。
- 依据与引用：核心表述支持于固定版本原件，来源规则、解释与实际验证可辨识。
- 链接与导航：页面从 INDEX 可达；目标存在之外，正文能承担链接所描述的作用。
- 目录与组织：职责不重复，新增内容落点合理，无占位页或原文堆砌。
- 一致性与更新：同一条件下的定义和结论一致，合理差异保留条件。
- 当前状态与缺口：SELF、INDEX 与实际材料及页面对应；未验证情形不写成已通过。

raw 只做基础查看；关键引用再定向回查。结构检查与内容核验分别报告。共享入口越出示例 root 时保留提醒，再从仓库 root 核对；局部检查不推断全局导航。疑点、确认问题和改进建议分开，并说明实际未覆盖部分。
