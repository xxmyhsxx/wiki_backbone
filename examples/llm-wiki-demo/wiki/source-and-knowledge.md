# 来源与知识为什么分开

这页解释 LLM Wiki 的三个部分各自保存什么，以及为什么“来源已保存”不能直接等同于“知识已形成”。它帮助初次使用模板的读者判断资料应放在哪里。新增资料如何更新已有页面，见[入库与维护](ingest-and-maintenance.md)。

## 三个部分各有职责

Karpathy 在原始说明中提出三层结构：原始来源保存取得的资料；Wiki 保存 Agent 整合的知识页面与关联；工作约定说明页面结构、引用和任务如何执行。这是作者提出的工作模式，具体目录和工具可以随用途确定。[依据：原件 Architecture](../raw/2026-10-13/karpathy-llm-wiki/original.md#architecture)、[Note](../raw/2026-10-13/karpathy-llm-wiki/original.md#note)。

| 部分 | 本示例保存什么 | 阅读时怎样使用 |
| --- | --- | --- |
| 来源资料 | 固定版本的 `original.md`、忠实副本 `article.md` 与来源说明。 | 回查作者实际上说了什么、用了哪些条件。 |
| 知识页面 | 围绕读者的问题组织中文解释，必要时整合多份材料。 | 先理解问题，再沿引用回到原件。 |
| 工作约定 | 用途、页面职责、来源形式、入库与检查方法。 | 判断 Agent 这次应该读取和修改什么。 |

表中的文件安排是本示例沿用模板规则作出的选择。原始说明没有要求所有 Wiki 使用这套文件名或统一分类。

## 保存与理解是两种结果

原始说明强调持续维护的知识层：新来源不仅被保存，还会用于补充既有解释、关联与综合判断。[依据：The core idea](../raw/2026-10-13/karpathy-llm-wiki/original.md#the-core-idea)。本示例据此区分资料归档和知识整理：归档确保日后能够回查，知识页则需要解释读者关心的问题、条件与来源之间的联系。

例如，“取得一份讨论 Wiki 的文章”只证明资料已保存；“解释来源与知识的职责，并注明依据”才形成可复用的页面。这个例子是整理者对两种结果的说明，不是运行效果数据。

## 来源支持什么，也限制什么

引用原件可以证明作者表达过某项观点，不能单凭引用证明观点在所有任务中成立。原始说明是设计想法，其中关于维护成本和规模的表述没有在本示例中做效果复现。这里保留结构与操作思想，不把它们写成准确率、成本或可靠性保证。

本页能够承接“来源与知识怎么区分”；是否应该为某份材料新增页面，还需读取[入库与维护](ingest-and-maintenance.md)并核对已有正文。
