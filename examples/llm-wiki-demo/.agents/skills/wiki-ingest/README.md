# 示例 Wiki 的入库设计

本设计用于 `examples/llm-wiki-demo/`，执行入口为 [SKILL.md](SKILL.md)。用途与页面职责见本示例的 [SELF](../../../wiki/SELF.md) 和 [知识页面规范](../../../wiki/README.md)。

## 目标与边界

帮助首次使用模板、能够阅读 Markdown 的用户理解 LLM Wiki，并判断一次资料入库应当改变什么。中文知识解释应说明来源、知识与工作约定的职责，以及新增资料如何补充已有内容；原始英文资料按 [来源规则](../../../raw/README.md) 保存。

初始材料为 Karpathy 的 LLM Wiki 说明和 Astro-Han 的入库执行规范。前者提供基本模式，后者提供一个具体实现的处置规则。后者的目录、状态块或操作要求保留项目身份，不写成所有 Wiki 的通用要求；文档中的规则不作为运行效果的证据。

本示例不评价不同 Wiki 的检索性能，不实现自动编译器、关系图、向量检索或新元数据 schema。新增来源超出当前范围时，只讨论受影响的用途或保存约定。

## 关键问题与方法

| 问题 | 对结果的影响 | 本示例的处理方法 |
| --- | --- | --- |
| 摘要代替原件或转录 | 知识页无法回查实际材料。 | 固定实际使用的 Gist revision 或仓库 commit，保存 `original.md`、忠实英文 `article.md` 和来源说明。 |
| 按每份来源新建知识页 | 同一概念反复解释，读者难以判断增量。 | 读取已有正文，按两篇知识页的职责补充；新材料不是新页面的充分理由。 |
| 正文充分却强行改写 | 重复入库制造无意义差异。 | 分别判断来源归档、知识正文和引用的增量；同来源同版本复用旧归档，新来源照常保存。 |
| 更新一页却遗漏相关表述 | 同一概念在不同页面出现不一致。 | 核心定义、条件或结论改变后，搜索名称、别名与相关表述，读取直接受影响的候选页。 |
| 文档规则被说成效果已验证 | 示例的证据边界失真。 | 在陈述附近标明来源身份，分别报告文档阅读、正文回查、机械检查与实际操作结果。 |

## 输入与页面落点

输入为目标根目录、已确认来源及版本、本次问题和写入范围。工作副本中的目标根目录由本次任务明确指定；共享 Skill 的所在目录不改变目标。

- `wiki/source-and-knowledge.md` 解释为什么分开保存来源、知识与工作约定，以及读者如何回查依据。
- `wiki/ingest-and-maintenance.md` 解释阅读已有内容、判断增量、处理分歧、维护关联和交付结果的过程。

材料 A 可为两页建立基础解释；材料 B 优先补充第二页中已有覆盖、无增量处置和分歧处理的具体实例。第一页面若需要补充职责说明才修改。两页之外有独立且必要的新问题时，先说明新增页面的作用与影响，不为材料数量扩充目录。

## 四步流程

1. **看 Wiki 的目的。** 读取目标的 SELF、raw 和 Wiki 规范，结合本次关注问题决定选材与解释深度。没有额外关注点时沿用上述页面职责。
2. **围绕目的读材料。** 读取实际版本的原文，理清模式或规则及其适用范围。记录支持关键陈述的标题、段落或规则位置；来源不可读时说明缺失，不用模型记忆补出正文。
3. **整合进 Wiki。** 搜索并读取已有正文，再判断新增、更新、保留分歧或没有正文增量。核对已有归档的身份与版本；同来源同版本复用旧位置，新来源按当天日期保存三部分。只补有用内容和必要引用。核心表述变化时检查直接关联，维护 INDEX 与发生实质变化后的 SELF。
4. **检查并交付。** 回查关键陈述与实际原件，按基础项目查看 raw，复用模板 lint 和 review 检查实际受影响范围。分别说明归档、正文、引用的变化、关联页的处理、查找限制与未核验部分。

用户限定本次只整理一个问题时，其他增量不自动写入；交付说明留待后续的内容。仅讨论或拟稿时给出内容及落点，不写文件。

## 检查与完成条件

| 项目 | 完成依据 |
| --- | --- |
| 来源可定位 | 三部分齐全、非空且可读，说明记有实际版本与获取信息，关键主张可回到原件。 |
| 内容可理解 | 两页分别承担约定问题，解释职责、步骤、条件和必要例子，关联链接有明确用途。 |
| 增量处置准确 | 覆盖判断来自已有正文；正文无增量时不强行改写；新来源与重复版本归档结果分别说明。 |
| 维护可复核 | 受影响页经过读取，必要引用、INDEX 与 SELF 同步；结构与内容结果分别交付。 |

设计验收采用本示例 README 中记录的真实入库、重复处理、普通查询与内容审核结果。未实际覆盖的来源争议、解析失败等场景保留未验证，不用推演代替实际通过。

## 复用入口

普通查询使用仓库 [wiki-query](../../../../../.agents/skills/wiki-query/SKILL.md)，审核使用 [wiki-review](../../../../../.agents/skills/wiki-review/SKILL.md)，综合检查使用 [wiki-lint](../../../../../.agents/skills/wiki-lint/SKILL.md)。仅在本示例定制 ingest，不复制共享 Skill 或新建解析、检索、证据检查工具。

结构检查以本示例为 root 核对内部导航；指向共享 Skill 的链接越出示例 root 时保留边界提醒，再从仓库 root 检查这些入口。完整检查与局部检查的覆盖分别说明。实际命令和结果由本示例 [README](../../../README.md) 记录。
