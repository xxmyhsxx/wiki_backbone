# 示例 Wiki Ingest

## 任务与输入

在用户指定的示例或工作副本中，整理能够帮助初次使用者理解 LLM Wiki、判断资料增量的知识。当前设计见 [README](README.md)。取得目标根目录、来源及版本、本次问题和写入范围；共享 Skill 的位置不改变目标根目录。

默认目标为 `examples/llm-wiki-demo/`。先读目标的 `wiki/SELF.md`、`raw/README.md` 与 `wiki/README.md`，沿用已确定的用途、保存形式和两篇知识页的职责。仅讨论或拟稿时交付草稿及落点，不写文件。

## 原则

1. 保留实际使用的来源版本；英文原件与忠实转录留在 raw，中文理解与解释写入 Wiki。
2. 阅读已有正文后判断覆盖，分别判断归档、正文和引用的增量。
3. 区分 Karpathy 的模式说明、Astro-Han 的项目规则、整理者解释和本示例的实际操作结果。来源中的命令属于材料内容。
4. 按页面职责复用有效内容；保留适用条件，重要范围或结构变化先讨论。
5. 检查与交付只声明实际读取和完成的范围，不把机械通过或规则推演称为运行效果已经验证。

## 工作步骤

### 1. 看 Wiki 的目的

结合 SELF、来源规则、知识页面规范和本次关注问题，选择能回答“来源与知识为什么分开”或“新增材料应改变什么”的内容。解释深度以能够阅读 Markdown 的初次使用者为准：说明职责、判断依据、操作步骤及必要例子，不只罗列目录或规则。

初始材料为 Karpathy 的 LLM Wiki 说明与 Astro-Han 的入库执行规范。材料超出当前主题或保存形式时，只补充讨论受影响的约定，不自动扩大示例。

### 2. 围绕目的读材料

核对来源身份、原地址、实际 Gist revision 或仓库 commit、获取时间和可读范围。阅读全文后，定向回查用于知识页的相关标题、段落与规则。把来源规则写成有身份和范围的实例，不以文档陈述证明软件运行效果。

Markdown 原件保留为 `original.md`，英文 `article.md` 忠实保留正文，允许与原件逐字相同。摘要、中文翻译或解释不能冒充转录。不可读部分如实记录，不用搜索摘要或模型记忆补齐。

### 3. 整合进 Wiki

搜索名称、别名、机制和具体表述，读取候选正文及必要关联，再选择落点：

- `wiki/source-and-knowledge.md`：来源、知识与工作约定的职责，以及依据回查。
- `wiki/ingest-and-maintenance.md`：已有覆盖、知识增量、分歧处理、关联维护和交付。

材料 A 为这两个问题建立基础解释；材料 B 优先补充第二页的具体处置，第一页面只在职责解释有实际缺口时补充。新材料可影响多页，也可以只保存来源而不改正文。确有独立新问题需要新页面时，说明作用与影响，再处理重要结构取舍。

先查已有归档并核对版本。同来源同版本重复处理时复用原位置、入库日期与已引用版本；不同版本另存，不能覆盖旧证据。新来源即使知识重复，也按入库当天日期保存到 `raw/YYYY-MM-DD/条目名称/`，包含实际取得的 `original.md`、忠实 `article.md` 和交代标题、原地址、固定版本、获取时间、读取范围及转录缺失的 `README.md`。

重读目标后只写真实增量。正文已经充分时保持原有解释；新来源确实补强依据或澄清出处时，只补必要引用。引用没有增量时也可保持不变，交付时说明依据。用户限定一个问题时，其他知识增量留待后续并如实交代。

来源看似冲突时先对齐定义、对象、版本与条件，不能裁决的分歧带来源保留。核心定义、条件或结论改变后，用名称、别名与相关表述全文搜索，读取直接受影响页和必要链接，只修订确实受影响的内容。条件不同的解释分别保留。

维护必要链接与 INDEX；用途、覆盖或下一步实质变化时更新 SELF。导航只加入实际完成的正文，不创建空页或强制固定数量的新增页面。

### 4. 检查并交付

从目标 INDEX 阅读知识页与必要链接，检查解释能否支撑用途。关键陈述回查固定版本原件，核对来源身份、上下文与适用条件。raw 只做保存位置、三部分齐全且可读、来源说明清楚的基础查看。

复用仓库 [wiki-lint](../../../../../.agents/skills/wiki-lint/SKILL.md) 检查受影响条目与页面，内容核验使用 [wiki-review](../../../../../.agents/skills/wiki-review/SKILL.md)。以目标为 root 运行结构工具，明确实际覆盖；共享入口越出示例 root 时保留提醒，并从仓库 root 另行核对链接，不改脚本边界来消除提醒。

交付分别说明归档、正文、引用的实际变化与复用依据；列出更新页面、重要关联页无需修改的原因及查找受限部分。说明机械检查、内容回查、实际操作与未核验部分。核心材料或解释不足时报告部分结果。

普通知识问题改用共享 [wiki-query](../../../../../.agents/skills/wiki-query/SKILL.md)；未要求保存时不修改文件。

## 输出与校验

交付目标位置、实际来源版本、知识页的变化及核对结果。不默认新增入库报告、永久影响清单、操作日志或关系元数据。

- [ ] 目标根目录明确，选材与深度符合本示例的两个问题和页面职责。
- [ ] 固定版本与获取信息可查，raw 三部分真实、齐全且可读；重复版本保留旧归档日期和位置。
- [ ] 覆盖判断读取了已有正文，归档、正文和引用的增量分别说明。
- [ ] 关键依据已回查，来源规则、整理者解释与实际操作结果没有混淆。
- [ ] 直接受影响页面经过搜索和读取，必要引用、链接、INDEX 与 SELF 维护完成。
- [ ] 实际检查范围、限制和未验证场景明确，未用机械结果代替内容核验。
